Do not repeatedly wake them in this release session. The web candidate shows CURRENT, STALE, INCOMPLETE, AWAITING PUBLICATION and MISSING COST. Historical inventory gaps and historical cost differences remain disclosed. V4 arithmetic passing does not certify that an unpublished interval or missing costs are economically complete.

## Hosting comparison (official sources checked September 20, 2026)

Prefer Netlify in the existing `orion` workspace. No additional team is needed. The GitHub repository is public and owned by a user, so private-organization repository restrictions do not apply. The published Free plan is $0 with 300 credits/month; Personal is $9/month with 1,000 credits. A production deploy consumes 15 credits. Keep the existing plan, auto-recharge and upgrades unchanged; review actual workspace usage before approval. Free quota exhaustion pauses service, so the beta must tolerate that limit or the owner must separately approve a paid plan. [Official pricing](https://www.netlify.com/pricing/).

Netlify's OpenNext adapter supports App Router, route handlers/server rendering and middleware, mapping these to Functions and Edge Functions. Retain Node 22, `npm run build` and `.next`; no static export or legacy adapter. Local build success is not proof of the provider's packaging, export runtime limits or HTTPS cookies. Record the adapter version and validate them during the approved deployment. [Official Next.js support](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/).

Cloudflare offers Free Workers and a paid subscription starting at $5/month plus usage. Its current guidance recommends vinext for new Next.js apps and documents OpenNext for existing applications. Moving this repository would require runtime/adapter, cookie, Node dependency and PDF/XLSX export compatibility work. No demonstrated advantage justifies that additional release work here. [Runtime guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/opennext/), [pricing](https://developers.cloudflare.com/workers/platform/pricing/).

Render supports the complete Next.js application as a Node web service, with normal server routes/middleware and environment secrets. Free web services sleep after 15 idle minutes and have monthly hour limits; always-on instances cost extra. The current pricing page did not expose a reliable exact Starter quote in the retrieved page, so this card does not invent one. A switch would add provider setup without reusing the existing Netlify preparation. [Next.js deployment](https://render.com/docs/deploy-nextjs-app), [official cost model](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses).

## Proposed recurring cadence — remains disabled

Start conservatively after a separate reviewed activation: commercial once daily at 08:00 Moscow, one inventory capture per account/day after commercial, current-stock twice daily at 08:30 and 20:30, Ads daily at 09:00 using its existing 14-day overlap. These are proposals, not the behavior of the current hourly workflow. Implement/rehearse an explicit task/time selector before enabling; do not simply flip the existing hourly opt-in.

Keep one global worker at a time and per-account Finance fencing. Finance gets at most one daily pending check; if evidence is missing, stop until the next authorized evidence refresh/check rather than looping. Establish ownership of the existing publication-metadata producer first. Data-page continuation remains bounded, at least 70 seconds apart. Ads fullstats requests remain at least 20 seconds apart; the accepted baseline needed one request for A1 and two for A2, but campaign growth can increase this. Preserve the worker deadline and stop on errors instead of retry storms. Reconsider cadence only after observing quotas and actual freshness needs.

Revoke beta access using the documented claims/session procedure if needed; do not delete business history.
